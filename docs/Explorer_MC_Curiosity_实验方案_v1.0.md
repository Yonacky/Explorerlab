# Explorer MC Curiosity 实验方案
## 从主动实验到可验证知识：可实施、可预注册的 v1.0 协议

版本：v1.0｜日期：2026-09-21｜状态：实施设计，尚未运行 Minecraft 实验

## 执行摘要

本方案首先检验一个有限而明确的命题：**在相同的屏幕输入、低级操作、感知、记忆和计算预算下，知识缺口驱动的实验选择，能否比新奇性、学习进展和一般语言模型选择，更有效地获得可独立检验、可用于新目标的知识。**

主实验不是直接放进原版 MC 漫游数小时。先制作一个运行在 Minecraft Java 中的匿名、规则随机化小型实验场，控制可达性与动作难度；随后用独立预测测验、清空物品后的新目标测试，以及同经验流的记忆对照建立证据链。最后才做两小时 Overworld 扩展。受控实验的成功，不能直接声称掌握了原版 Minecraft 或开放式自主科学发现。

核心交付为一套环境规范、五个主对照臂、统一运行预算、四十八项隐藏预测测验、四个迁移目标、证据图与日志接口、分析规则和逐级验收门槛。文末列出实施顺序；配套文件提供配置、SQLite 结构、空白数据模板和离线分析脚本，不包含已完成的 MC 模组或实验结果。

| 决策项 | v1.0 固定方案 |
|---|---|
| 研究平台 | Minecraft Java 1.21.1；Fabric 研究模组；Peaceful；屏幕输入与低级键鼠 |
| 主环境 | 8 类机制、每类 3 个可接近实例；匿名外观；每个世界独立重排规则与产出图标 |
| 主对照 | Random-C、Novelty、LearningProgress、LLM-Choice、Explorer；共享知识图与执行基础设施 |
| 单次探索上限 | 24,000 个有效模拟 tick；96 个实验决策轮；另设模型与图像预算；先触及者停止 |
| 主样本 | 32 个独立世界配置 × 2 个智能体随机种子 × 5 臂＝320 次；最终数量在 pilot 后、测试前冻结 |
| 主要终点 | 隐藏预测集上的 Brier 损失改善；主比较为 Explorer 对 Novelty / LearningProgress / LLM-Choice |
| 关键外部检验 | 新布局、空物品栏、相同规则下，4 个图像目标的完成率与截断完成成本 |
| 最小实施边界 | 不训练 RL / Dreamer；不向执行器提供 mine、craft、navigate_to；主实验不启用新学宏技能 |

## 1. 材料依据、保留项与设计变更

### 1.1 来自上传材料的约束

[S1] 最新讨论明确提出：一个一般推理模型、匿名对象感知、低级 MCP 执行器、显式知识记忆；不提供坐标、方块 ID、物品名称、recipe、Wiki、示范或任务奖励；先不训练 RL 或大型 world model。探索后通过物品参考图提出新目标，而不是使用领域名称。[S1，§1–4、§7、§9、§11–12]

[S2] 交接总结明确提出：区分 novelty、prediction error、epistemic uncertainty 和 learnability；以 experiment 为选择单位；保存证据、条件与置信信息；Transport Before Dynamics；评价知识发现、知识质量和后续用途。[S2，§3–8、§12、§15、§25–28]

此前讨论形成的数据结构建议在本方案中落实为：Anchor、Claim、Episode、Procedure、Question、Justification 六类节点，带情境、时间、版本与依据关系；每轮读取有预算的工作子图。它是待验证的架构选择，不是已被实验支持的结论。[D1]

### 1.2 明确新增或调整的部分

| 材料中的设想 | 本方案的处理 | 理由与结论边界 |
|---|---|---|
| 初次直接在 Overworld 探索 2–4 小时 | 改为受控场主实验；保留 2 小时 Overworld 扩展 | 避免导航、资源稀缺和预训练记忆掩盖选择机制；不是声称实验场等同原版世界 |
| 四个系统级 baseline | 主实验增加 LearningProgress；LLM 自由探索另设扩展 | 先隔离 selector；完整自由探索会同时改变问题生成和计划质量 |
| Curiosity + Memory 对无 Memory | 主臂全部使用同一记忆；另用同经验流比较组织方式 | 防止把记忆容量优势误认作实验选择优势 |
| JS divergence 作为 knowledge gain | 仅记为 belief shift，不能作主终点 | 信念改变可能更错；独立预测和复验才评价知识质量 |
| 熵高就优先、低学习进展就放弃 | 分开参数不确定性与结果随机性；允许暂缓及重开 | 随机机制的分布也可学习；困难前置条件不能等同不可学习 |
| 成功率超过 0.9 即入 Skill | 主实验只记录技能候选；独立技能分支再测 | 少量重复成功不能自动证明可靠性；避免宏动作改变预算与执行能力 |

上述变更均为本方案新增设计，不将其追认为附件已达成的结论。Plan2Explore 已研究无任务监督探索与后续适应，因此“不用任务奖励”本身不是新颖性主张。[R1]

## 2. 假设、归因与允许的结论

### 2.1 确认性主假设 H1

在相同基础设施与预算下，Explorer 在最终隐藏预测集上的知识增益，高于 Novelty、LearningProgress 和 LLM-Choice。主要因变量不是内部 curiosity 分数、发现节点数、移动距离或任务物品数量。

### 2.2 机制假设 H2

Explorer 应逐步减少对已掌握随机机制的无增量采样，同时仍能研究有规律的复杂机制，并在获得前置物品后重新研究原先失败的机制。必须同时测“噪声重复”和“难问题遗漏”，不能只奖励远离噪声。

### 2.3 记忆与迁移假设 H3

已积累的知识在重置世界物质状态后，应改善新目标表现；在相同经验和内容下，证据图应比平面证据索引更便于检索反例、修订条件和保持预测。前者检验知识的使用价值，后者检验组织方式，不能合并归因。

### 2.4 六项好奇原理的覆盖范围

| 原理 | 本轮能观察的证据 | 本轮不能据此声称 |
|---|---|---|
| 增加知识、发现规律 | 独立预测改善、跨实例复验 | 全领域知识增长或未知总量单调下降 |
| 记忆与知识化 | 证据可追溯、重置后迁移、同流记忆对照 | 显式图是任何好奇系统的必要条件 |
| 预测与实验 | 事前预测、竞争假设、对照与执行核验 | 每项自然语言解释都是因果发现 |
| 无直接实验时外推 | 禁止追加交互的隐藏预测测试 | 高自报置信度代表正确认识 |
| 改进知识结构 | 类别复用、条件拆分、预算内检索 | 自动发现最优本体或无限开放概念 |
| 主动制造新情况 | 持有物品、改变站位条件、组合操作 | 本轮已证明无界开放式环境创造 |

## 3. 整体实验链：M1＋M2＋M3，E1 作为扩展

**M1：在线探索主实验。** 五臂独立探索各自复制的相同世界；保存 0、12,000、24,000 tick 的知识快照；在不回流答案的副本中评估预测。

**M2：同经验流的知识组织检验。** 从 Explorer 与 Novelty 的最终日志提取相同的屏幕来源事实、候选命题和证据引用，分别重放到证据图与平面证据索引。固定提取器和输入内容，不额外让某一组获得人工解释。此项不需要重新探索 MC。

**M3：清空物品后的知识迁移。** 从 M1 最终知识快照建立全新会话，进入新实例、新布局、相同规则的重置环境。给四个图像目标，比较五臂探索知识和一个空知识控制。每个目标独立重置，禁止把前一个任务经历带到下一个。

**E1：Overworld 外部效度扩展。** 主实验完成后，比较完整 Explorer、Novelty＋同图、LLM-Free＋同图；保留无名称、低级操作和匿名纹理设置。此项不与 M1 数据合并，也不替代 M1 机制归因。

## 4. 平台、时钟与信息隔离

### 4.1 版本与运行方式

基准开发目标固定为 Minecraft Java 1.21.1、JDK 21、Fabric Loader 0.16.14、Fabric API 0.116.4+1.21.1。后两项发布件在官方 Maven 可查；选择历史固定版本是为减少接口漂移，不是宣称其为当前最新版。实际模组编译、启动与依赖兼容必须经过 G0 验收；Gradle、Loom、映射、模组 JAR 与资源包 SHA-256 一并写入冻结清单。JDK 21 与 1.21.1 的对应参照该版本官方文档。[R2–R4、R11]

模组暂定名 ExplorerLab，只承担环境生成、匿名资源、研究者评估与确定性调度。它不是智能体控制策略。客户端运行在隔离桌面，智能体进程无游戏目录、进程内存、网络包、研究者端口与环境配置读取权限。

主实验采用 step-controlled clock：语言模型思考期间暂停世界有效模拟；输入块执行时推进指定 tick，并保存实际推进数。不是仅降低 TPS，也不是只暂停玩家而让机关继续变化。客户端渲染可继续，所有实验相关动画与随机变化必须由同一有效时钟驱动。该调度是待实现功能，G0 不通过就不得把结果标为严格等交互预算。

观察不会推进世界，只返回当前帧；重复读取同一帧仍计入感知调用预算。最长低级输入块为 40 tick；一个实验含多个块，总上限 300 tick。跨块的保持动作由执行器显式维护，实验结束、异常或超时必须释放所有按键。

### 4.2 智能体与评价器的权限边界

| 信息／能力 | 智能体侧 | 研究者侧 |
|---|---|---|
| RGB 截图及由其计算的 mask / embedding | 允许 | 允许 |
| 键鼠输入、请求持续时间、工具是否成功投递 | 允许 | 允许 |
| 坐标、block/entity ID、射线命中、物品栏 JSON | 禁止 | 可用于审计与评分，不回传 |
| 掉落／配方／条件规则表及随机种子 | 禁止 | 仅私有生成器与评分器可见 |
| 世界重置、传送、设置隐藏条件、oracle 路径 | 禁止 | 仅初始化、离线测验与验收 |
| 真实执行是否命中对象 | 不能直接回传；从屏幕估计 | 记录用于故障归因 |
| 预测测验答案、下游成功判定 | 探索期禁止回流 | 冻结后离线评分 |

MineDojo 文档中的 inventory、location、voxel 等结构化观察说明了需要阻断的通道；本方案不把这些字段送入智能体。[R5]

### 4.3 先验与泄漏审计

允许通用按键说明、UI 区域类型、数字槽位选择与鼠标取放操作；不说明任何对象名称、作用、条件、产出和配方。不使用预训练 MC 专用策略、示范轨迹或游戏攻略。允许一般预训练 VLM，但不声称它没有 MC 先验。

移除或替换聊天、F3、高级 tooltip、物品名、配方书、成就与教学 toast、计分板、调试标记和资源文件名等可见泄漏。声音不进入模型。图标可有数量，不显示领域名称。匿名 ID 由智能体 Registry 生成，不由真实方块 ID 派生。

研究者配置和 agent 配置使用不同文件与权限。agent 配置不能包含世界种子、机制分组、图标映射、规则版本变化时点或隐藏测验内容。只允许受控模型端点网络请求；模型不得获得外部浏览工具。

## 5. 主环境 ExplorerLab-8：可制作的匿名 MC 实验场

### 5.1 几何与资源安排

在 Overworld 平坦区域建立 48×48 方块的安全实验场，布置 5×5 的站点位置，其中 24 个位置容纳 8 类机制各 3 个实例，1 个为空位。站点间通道至少 3 方块宽；地面不可破坏，无战斗、坠落、岩浆或时间天气干扰。实例均可从正常步行路径接近；所有实验目标保持视觉可分辨。

站点排列、初始朝向、纹理、图标、阈值与规则映射独立抽样。功能类别在单世界内具有可学习的稳定外观标识，同时加入与功能无关的次级纹理变体。跨世界重新打乱外观与功能对应；不能把某一种显眼纹理固定分配给噪声。

本环境的自定义装置、可重复触发及图标产出是研究装置，不伪装成原版方块机制。为降低资源管理混淆，基础产出装置可重复获得图标；冷却期统一并可观察。组合装置按明确规则消耗输入。所有组面对相同可供学习的机会。

### 5.2 八类机制的研究者规格

下表中的 M01–M08、A–F 和变量名只用于环境代码与评分器，绝不写入 agent 提示。

| 类型 | 世界中的操作规则 | 每个世界随机化 | 主要检验点 |
|---|---|---|---|
| M01 持续作用 | 对准并持续主要动作达到阈值，外观改变并产出图标 A；短于阈值不产出 | 阈值取 8 / 20 / 32 tick；A 图标与外观映射 | 比较持续时间，而非只尝试不同对象 |
| M02 次要动作 | 对准执行一次次要动作，指示状态改变并产出 B；主要动作不产出 | B 图标、外观、初始指示状态 | 同对象不同动作的 affordance |
| M03 物品条件 | 选中正确前置图标并执行次要动作，产出 C；空手或错误图标不产出 | 正确前置为 A 或 B；每世界重新选取 | 获得新物品后重新打开问题 |
| M04 情境条件 | 玩家站在相邻两个可见地面区域之一，主要短动作才产出 D | 有效区域标识与左右位置独立重排 | 主动改变情境，发现条件变量 |
| M05 延迟结果 | 一次次要动作后，延迟出现指示变化并产出 E；等待本身不启动 | 延迟取 20 / 60 tick；待触发期锁定重复触发 | 把“暂未观察到”与“不会发生”分开 |
| M06 双输入组合 | 次要动作打开两个输入槽；将 C、D 按正确顺序放入后出现 F；错误排列无 F | 正确顺序为 C-D 或 D-C；图标全重排 | UI 实验、组合、依赖链与新情境 |
| M07 可学习序列 | 主要短动作推进到下一个可见符号；四个符号形成固定循环 | 符号外观与循环次序随机置换 | 结果丰富但有规律；需要历史条件 |
| M08 随机序列 | 相同操作产生四符号之一，独立均匀抽样 | 符号外观置换；独立 PRNG 子流 | 学会分布，而非永远预测下一次具体符号 |

M07 与 M08 的尺寸、可达性、符号边际频率和背景动态纹理强度相匹配；区别在时序依赖而非视觉显著性。两个面板均有与机制无关的动态纹理，避免把“有动画”固定等同于噪声。噪声标签不提供给算法。

M03 与 M06 的前置资源可通过 M01/M02 等基础机制取得，不能把关键物品藏到当前环境不可达处。M04 的两个条件必须可从屏幕区分；不使用智能体无从观察的隐藏开关，制造虚假的不可学习任务。

### 5.3 具体模组模块

EnvironmentGenerator 生成几何和配置；AnonymousResourcePack 生成图标、材质与无语义文本；MechanismEngine 执行八类状态机；StepController 管理有效 tick；ResearchLogger 记录隐藏状态和输入；ProbeRenderer 生成测验副本；SnapshotManager 保存与恢复完整世界、物品栏、机关状态和随机发生器。

主动作长按需读取正常输入造成的持续作用事件，而不是根据 planner 的 experiment JSON 直接触发结果。低级桥只注入键鼠；研究者日志才能读取真正命中的对象。组合界面使用普通鼠标取放逻辑，不提供合成函数。

### 5.4 生成器验收与可解性

每个配置在分组运行前，通过独立脚本或研究者 oracle 验证：全部站点可达；阈值规则正确；错误动作不会产出；M05 延迟符合配置；M06 两种排列结果不同；M07 循环可预测；M08 使用独立子流。随机机制按对象与触发次数生成随机值，避免不同动作数量改变全局 PRNG 后造成不必要的组间耦合。

oracle 只验证环境与可解性，不向模型展示路径。实例、截图和规则清单在测试前生成并哈希封存，不根据任何方法的测试成绩挑选世界。生成器无效配置按预注册条件自动剔除，并记录原因。

## 6. 感知、执行和知识图的最小实现

### 6.1 SAM 3 只负责匿名视觉，不提供名称

使用 SAM 3 的视觉点、框、mask 或 exemplar 提示；初次用固定网格和视觉区域候选发现目标，随后按当前关注对象追踪，保留 mask、匿名对象 ID、裁剪与视觉相似度。官方仓库支持此类图像／视频提示，并给出运行依赖。官方仓库在 2026-03-27 已发布 SAM 3.1；本方案不自动升级，pilot 前固定一个 checkpoint 与代码提交，所有组一致。[R6]

感知服务与 agent 服务分开。禁止使用 tree、stone 等语义提示，禁止直接使用示例中的 text-prompt 工作流替代视觉提示而不披露。界面变化由截图 ROI 差异、图标匹配与 VLM 核验共同处理，不只依赖一句自然语言描述。

先做视觉匹配与自运动补偿，再标记残差；残差不是世界变化的充分条件。无法确认对象对应或执行效果时记录 ambiguous，并建立复查问题，不能强制记为“无效动作”。

### 6.2 低级工具与通用控制先验

允许 observe、move_mouse、key_down/up、mouse_down/up、press、scroll、wait，以及有时长上限的 hold。不暴露 mine、collect、craft、find_tree 或导航到世界坐标。执行器只能将当前视觉目标和模型提出的步骤编译为这些输入。

允许一个所有组共享的通用视觉伺服器：将选定屏幕区域移到准星、按像素位置操作 UI、监测画面是否稳定。它只使用截图，不读取射线或坐标；其规则和校准数据必须公开。这是显式通用动作先验，不声称完全从零习得运动控制。

主实验不调用新学技能宏。重复成功的动作序列可写入 Procedure 候选，技能执行优势留给扩展。这样 M1 的差异不能由某组多出 mine 风格操作造成。

### 6.3 证据图与有边界的工作子图

Anchor 保存匿名实例与原型；Claim 保存有条件、可修订的主张；Episode 保存屏幕和动作引用；Procedure 保存实验计划；Question 保存待澄清内容；Justification 保存证据、前提和推导方法。世界变化时间与记录修订时间分开。一次记录有多个解释时共享原始 Episode，不复制成多份独立证据。

工作子图上限为 64 节点、128 边、8 个展开的 Episode，文本记忆上限 4,096 token；超限时先保留当前目标、适用条件、反例和前置依赖，再做相关性截断。检索必须返回 truncated 标记。原始影像在外部存储，只按需读取。

每次更新：追加 Episode → 提出或修订 Claim → 写 Justification → 沿反向依赖查找受影响结论 → 更新问题队列与当前视图。新观察不能无条件覆盖旧观察；失效依据的其他独立支持需要保留。该溯源组织借鉴 PROV-O，语义—情节图组织参考 AriGraph；并不直接继承其任务表现结论。[R7–R8]

## 7. Explorer 选择器：第一版即可实现的规则

### 7.1 一轮的固定流程

读取当前截图和工作子图；更新执行与变化记录；生成最多 8 个可行候选实验；为每个候选写 target、question、竞争解释、操作计划、观察窗口、预期结果类别、预计 tick 成本；由对应实验臂选择一个；执行、保存前后证据并更新局部统计。

候选生成器只使用当前可见对象和自身记忆，不读取站点类别。问题来源为：尚未测试的操作、反例、条件外推、结果延迟、已获取新物品带来的新可行性。不要枚举所有缺失边。M1 各组使用同一生成器、版本和模板；历史不同后候选内容当然会不同，不能声称在线始终得到同一个候选集合。

### 7.2 局部概率模型与 EIG

对已定义的“对象原型＋动作＋视觉条件＋结果事件”建立 Beta(1,1) 或 Dirichlet(1,…,1) 统计。结果类别可以是可见状态变动、某图标出现或某个符号，而不是预置 M01–M08 标签。执行与观测可靠性不足时，不把结果硬计为否定；所有含糊事件仍计入探索成本。

若 α 是 K 类结果的 Dirichlet 参数，α₀＝Σαₖ，pₖ＝αₖ/α₀，则单次观测的模型内预期信息增益为：

    g(e) = H(p) + Σₖ pₖ ψ(αₖ + 1) − ψ(α₀ + 1)

ψ 为 digamma；以 log(K) 归一化。此量针对分布参数不确定性，不是结果熵本身。一个已采样充分的均匀随机源，其结果熵仍高，但参数 EIG 会下降。该定义依赖局部模型是否合适；并不保证真实知识一定增长。EIG 的实验设计用途参考 [R9]。

对于 M07 式历史依赖，允许在反复不一致后提出“前一可见符号”作为条件并比较预测。默认假设空间只包含屏幕可表达条件，不提供真实状态机。新增条件先作为候选，必须经后续记录验证，不能无限添加条件来解释每个训练样本。

### 7.3 Learning progress 与探索保底

内部记录按 episode_id 的固定哈希留出 20% 作为在线 probe；这些记录不参与对应统计模型参数拟合。每次比较当前与旧快照在同一已获得 probe 集上的 Brier 损失，取非负改善 LP。没有足够记录时 LP 为 unavailable，不认定不可学习；最终隐藏测验从不参与该估计。

默认启发式为：

    Score(e) = p_exec(e) × [g(e) + 0.5 × LP(e) + 0.1 / √(1+n_q)]
               / [1 + estimated_ticks(e)/40]

p_exec 由该通用执行方式的屏幕核验历史估计，n_q 是当前问题的有效证据数；不可用 LP 暂取 0。权重是工程初值，不是理论常数。pilot 只允许在预先限定的小网格中调整；最终参数在测试前冻结。

10% 决策采用同一可行集合上的均匀抽样，防止长期饿死新问题；该保底也施加于其余非随机主臂。得到新前置物品或反例时，暂缓问题可重开。新问题有初始正 EIG，不用 LP＝0 将其永久否决。

实际结果另记 JS belief shift、预测误差和信息收益估计，但这些都不是实验成败的最终指标。禁止根据隐藏测验调整 Score。

## 8. 五个主对照臂与公平性

| 臂 | 选择方式 | 共享部分与区别 |
|---|---|---|
| Random-C | 对已生成的可行实验均匀抽样 | 是随机实验选择，不是连续随机乱按键；不称为 RND |
| Novelty | 匿名目标／结果视觉 embedding 新颖度与访问次数衰减，除以同一成本项 | 不使用信息增益、知识问题价值或模型自报置信度 |
| LearningProgress | 使用同一内部 probe 的 LP、冷启动项和成本项 | 不使用显式 EIG；困难问题有相同探索保底 |
| LLM-Choice | 同一 LLM 看同一形式的候选、截图与记忆，直接选下一实验 | 不计算手工 curiosity score；不是完全自由探索 |
| Explorer | 第 7 节知识缺口与局部 EIG / LP 选择 | 其余能力同上 |

所有臂共享视觉模型、控制器、知识图、候选生成器、证据更新、上下文上限、模型版本和随机化设置。每轮最多 2 次规划／更新模型调用，每次输入上限 8,192 token、输出上限 1,536 token；单运行输入总上限 1,000,000、输出总上限 200,000 token。视觉 token 和实际费用单独记录。图像读取上限 2,400 帧。固定分辨率 1280×720、GUI scale 2、FOV 70、render distance 4 chunks；禁止着色器，所有组一致。固定缓存策略，不给某一臂额外重试额度。

模型调用槽位是上限，不要求随机臂浪费额外调用来制造相同账单。主要结论是相同可用预算下的效果，同时报告实际计算成本与质量—成本曲线；不能仅凭 tick 相同宣称算力完全相同。

Novelty 的默认分数为 [0.5×d_visual＋0.5/√(1+n_target_action)]/[1+estimated_ticks/40]；d_visual 是与此前主动关注裁剪集合的最小 cosine distance 除以 2，截断到 [0,1]，不把当前帧放入自己的参照集合。LearningProgress 的默认分数为 p_exec×[LP＋0.1/√(1+n_q)]/[1+estimated_ticks/40]。没有历史参照时 d_visual＝1；LP 不可用取 0，所有组保持相同冷启动与动作可行性规则。

另外，从 pilot 中冻结 40 个“同状态、同记忆、同候选”快照，让五种选择器离线选择，用隐藏的短程后续实验验证候选价值。此为 selector 诊断，不计入主测试样本，也不将 pilot 候选最优标签回传训练。

## 9. M1 完整运行流程与样本划分

### 9.1 数据集划分

DEV：8 个世界配置，用于调试感知、候选格式和环境可达性。PILOT：4 个独立配置×1 个 agent seed×5 臂，共 20 次完整运行，用于量级估计、预算瓶颈与参数冻结；不得与测试混用。TEST：默认 32 个独立配置×2 个 agent seed×5 臂，共 320 次。

world_config 是独立抽样的规则表、外观、布局与隐藏测验配置的组合，是主要统计单位。两个 agent seed 是同一配置内的重复；四十八个问题、视频帧、实例都不是四十八个独立世界。

资源不足时可先执行 8 个配置×2 seed×5 臂＝80 次可行性版本，但不得把小样本的不显著结果当作无效性证明，也不得未经功效分析称其足以确认假设。

### 9.2 单次运行

1. Runner 载入独立世界副本，验证哈希、清空记忆与物品、初始化机关和随机状态。只恢复所有组相同的通用控制校准，不恢复领域经验。
2. 保存 B＝0 的模型与空知识快照。预测测试在副本中进行，其问题、图像和输出不进入在线会话。
3. 进行无任务探索。每轮预登记短预测与实验目的，再执行；被动遭遇另行标记，没有事前预测就保留为空，不事后补写。
4. 达到 12,000 tick 时保存快照；达到 24,000 tick 或其他任一预算上限后结束。若先耗尽轮数／token，冻结最终知识，后续预算点沿用冻结预测，不能补给额外实验。
5. 写出退出原因、实际资源、所有失败与外部干预；冻结知识后运行隐藏预测与 M3 任务副本。

算法卡住、重复实验、自己关闭必要界面、错误丢弃物品均计入表现；不得当作基础设施问题删除。只有预定义的进程崩溃、硬件错误、输入桥丢包或版本不一致等外部故障可触发重跑。同一配置中按配对块处理技术故障，保留原始失败日志。

## 10. 隐藏预测测验：独立衡量“真的学会了什么”

### 10.1 固定四十八项问题

每种机制 6 项，共 48 项，分成四个等权族：基础动作 M01/M02；条件规律 M03/M04；时间与组合 M05/M06；规律与随机 M07/M08。每项是关于明确可见结果的二元预测，输出概率 p∈[0,1]。不使用研究者机制名或原版物品名。

输入包括新的目标实例截图、必要的短历史截图、视觉可见条件、通用动作序列和待判断结果的参考图。只问“执行这些操作后，在所示窗口内，是否出现这个图标／状态”。M07/M08 使用充分的当前符号历史；M05 明确观察时窗。条件中同时包含正例、反例和阈值附近情形。

不向模型提供用于打分的真实 θ。每种机制的模板数、正负与条件组合在预注册时冻结。每个配置的测验实例与布局不同于探索实例；纹理功能映射在同一世界内保留，测的是新实例和条件迁移，不把完全随机改纹理后无法辨认对象伪装为知识失败。

### 10.2 统一答题器与防回流

所有组用同一冻结 VLM 答题器、同一图像格式和检索预算；每次提问是独立无状态调用，只能读取该快照知识，不得执行动作、更新原图或读取前一道测试结果。不得通过 ground-truth ID 将测试目标直接连到正确 Claim；只能用允许的视觉匹配与文本／图检索。

无法识别对象或知识缺失时仍需给概率；缺失、异常或不合法输出按 p＝0.5 计入，并单独统计，不从分母删除。目标居中截图降低导航因素，但不提供真实 mask；可另外做一次 oracle 对齐诊断，只用于解释感知瓶颈，不纳入主得分。

### 10.3 主要分数与随机结果处理

对二元结果 Y、预测 p 和环境规则给出的真实发生概率 θ，使用期望 Brier 损失：

    L(p,θ) = θ(1−p)² + (1−θ)p²
           = (p−θ)² + θ(1−θ)

确定性事件 θ∈{0,1}；M08 的指定下一符号 θ＝1/4。每个族内部等权，再对四族等权平均，得到 BS_b。主要知识增益为 G＝BS_0−BS_final，越大越好；主比较使用同配置内的 G_Explorer−G_baseline。

采用期望损失是因为研究者知道自定义随机机制，能避免把单次随机好运当作知识。随机项 θ(1−θ) 不可消除；另报 excess Brier＝(p−θ)²，但不能要求随机机制的单次符号准确率接近 100%。同时保存实际环境重复触发结果，确认实现与声明 θ 相符。

主要终点为最终 G；BS 随预算变化曲线、曲线面积、各族表现和校准分箱为次要结果。测试模型的内部熵和自报信心不作为正确性的替代。

## 11. 规律发现、因果证据与噪声诊断

### 11.1 不按“写出多少句话”计分

Claim 先按对象原型、动作、条件、结果和适用范围去重。研究者用封存规则以及独立反事实操作检验候选规律；命名不同但语义相同的规则不能重复计数。研究者的真值匹配仅用于评分，不回写 agent 图。

报告已支持规律的 precision、覆盖率、跨实例表现与证据完整率。新颖但不属于八类预定义机制的主张单独盲审，不增加主要预测分数，不因系统输出更多主张自动获得优势。

### 11.2 什么时候可以称为“因果规律候选”

至少包含：明确操作变量、可见条件、匹配的未执行／替代动作比较、执行可靠性核验、重复结果和潜在替代解释记录。通过后仍称为“在该场景与条件范围内获得干预支持”，不概括为无条件世界因果律。

研究者可在重置副本中保持初始状态、改变动作或一个条件检验真值。仅有 action 前后截图差异的 Claim 归为关联性／转移预测，不计入干预支持规则数。对象消失但视角同时改变时必须额外复查。

### 11.3 噪声规避与困难问题不能互相替代

记录 M08 交互占比、后半程新增证据的边际预测改善、M07 规律掌握情况，以及 M03/M06 的前置物品获得后首次有效复查延迟。后两项能发现“避噪声但也避开所有难题”的退化。

M08 诊断额外在每 4,000 tick 保存只读快照，读取四符号预测分布，不执行完整 48 题，也不向在线进程回流；因此“连续两检查点”不是只依赖中点与终点。定义冗余噪声采样诊断：当独立快照中 M08 的四符号分布预测已达到总变差距离≤0.10，且连续两个检查点保持时，随后对同条件的重复触发计为潜在冗余。阈值是诊断设定，不由 agent 读取；尚未学会分布前的采样不称为浪费。主要结论仍由整体知识增益与困难机制覆盖共同决定。

## 12. M2：相同内容下检验“有边界证据图”

### 12.1 输入与两个组织条件

使用 M1 中 Explorer 和 Novelty 共 128 条测试运行经验流。固定提取出的观察、候选命题、置信参数、反例和来源 ID，分别构建 Graph 和 FlatEvidence。FlatEvidence 保留同样的内容与证据字段，只去掉图遍历和显式反向依赖索引，使用文本／向量检索；不能故意拿一个无证据摘要当作对照。

两条件使用同一答题器、相同原始影像、相同 4,096 token 检索上限、相同调用数。图额外占用的存储和索引维护时间必须报告，不声称两种表示天然同成本。

### 12.2 测试任务

依次测试：找回某 Claim 的原始依据；找回被局部检索遗漏的反例；区分物体状态变化与旧判断错误；在已有条件被新证据挑战后定位受影响结论；重答相同隐藏预测问题。修订流来自真实 MC 屏幕事件或同一流中的真实后续记录，不注入只有某组看到的 oracle 标签。

为保证一定存在修订事件，另制作 12 条封存的共享屏幕诊断流，每条包含旧条件下重复记录、新条件下反例和无关稳定规律。诊断流在独立世界生成，所有内容均通过允许截图获得。它们用于结构机制诊断，不与 32 个主世界混充为更多独立探索样本。

主要 M2 指标是反例召回率和修订 precision/recall，辅以预测改善、出处正确率、p50/p95 检索延迟、图访问规模、上下文 token 和磁盘占用。若图更快却漏掉重要反例，不能判为成功。

### 12.3 归因范围

同经验流可以说明组织与检索差异，不能说明该结构在闭环中会产生更好的问题。后续资源允许时，再做 selector×memory 的在线 2×2 因子实验；本轮不将该未做实验写成既定证据。

## 13. M3：重置后的四个图像目标

### 13.1 测试设置

每个 M1 最终快照进入四个彼此独立的测试副本。清空物品栏，恢复机关初始状态，换布局与实例，不换该世界的规则与图标语义。原先对象位置和实例 ID 不再有效，只允许迁移原型、条件规律、证据和通用知识。启动新的 LLM 会话，不保留探索对话中的隐式上下文。

目标以参考图给出：“使这个图标出现在物品栏中”。任务期允许这一目标，但不提供 recipe、前置路径或 oracle 奖励。环境是否成功由研究者侧只读评分器判定，动作执行器仍只用截图。

| 任务 | 目标 | 所需知识；不向 agent 说明 |
|---|---|---|
| T1 | 图标 A | 基础动作类型与持续时间 |
| T2 | 图标 C | 获取并选中正确前置物品，再作用于目标 |
| T3 | 图标 D | 改变站位或局部条件，再执行操作 |
| T4 | 图标 F | 获得 C 与 D，找到界面并按正确顺序组合 |

每任务上限 3,600 tick、32 个决策轮、相同模型预算。允许在单任务内部获得新证据并更新临时记忆，但每个任务结束即丢弃该增量，下一个任务从原探索快照重新开始。主测试禁止调用新学技能宏，避免知识迁移与宏动作优势混合；Skill-on 分支是独立扩展。

### 13.2 对照与分数

五个 M1 来源各 64 个快照，加上相同配置／agent seed 的 NoExplore 空知识控制，共 384 个来源条件×4 任务＝1,536 个短任务。NoExplore 保留相同一般模型与通用操作先验，但不读取任何探索日志。

报告成功率、每任务截断完成时间 min(T,3,600)、动作成本和新增交互数；失败按上限计，不能只对成功运行计算速度。最后比较“探索成本＋测试成本”，以及一次探索服务多个任务的摊销成本。测试更快不自动表示总成本更低。

复制 Explorer 快照后清空其知识与全部会话，应与 NoExplore 条件一致；将这一擦除控制作为回归检查。知识保留与擦除的差异可支持记忆使用价值，但不能替代 M2 对图结构本身的比较。

## 14. E1：两小时 Overworld 扩展，不阻塞主实验

主实验通过验收后，在 8 个独立 Overworld seed、每 seed 2 个 agent seed 上比较 Explorer-Full、Novelty＋同图、LLM-Free＋同图。每次探索预算 144,000 有效 tick（按 20 tick/s 相当于 2 小时环境时间），实际墙钟时间另计。保留 Peaceful、低级输入、视觉匿名化；不探索 Nether、End、战斗和完整科技树。[S1，§12]

原版规则但随机纹理、以及少量掉落／组合规则重排，必须分开报告。至少采用规则重排条件，不能仅凭纹理随机化声称消除了预训练规则记忆。外部扩展会引入资源与导航难度，只能归因为完整系统。

本阶段才允许经证据登记的自学技能，并逐项记录技能何时形成、来自哪些轨迹以及节省多少低级 tick。LLM-Free 可自由生成目标和步骤，但使用同样输入与预算，不提供领域操作函数。

扩展指标仍为可复验规则、独立预测和重置后图像目标；位移距离、访问区域和物品种类只作描述。没有完成 E1 时，论文标题和结论应明确指向 controlled Minecraft laboratory，而非原版开放世界通用探索。

## 15. 统计分析、样本量与判定标准

### 15.1 配对统计单位

先对同一世界配置下两个 agent seed 的主要指标取平均，再在 32 个配置上计算组间配对差。使用以 world_config 为重采样单位的配对 bootstrap（10,000 次）报告 95% 区间；对三项预注册主比较做双侧配对 t 检验并采用 Holm 校正，α＝0.05。bootstrap 区间标为未作多重校正的估计区间，不误称同时置信区间。检查离群与偏态，稳健／配对置换结果作为敏感性分析，说明其交换性假设。

Agarwal 等的研究强调少运行次数下不确定区间与聚合方式的重要性；本方案借用其评价纪律，并不因为本系统不训练 RL 就忽略运行随机性。[R10]

### 15.2 样本量的实际含义

32 配置是计划值，不是已经证明具有足够功效。pilot 后只利用开发／pilot 数据估计配对差标准差 σ_d，并在隐藏测试前计算：

    n ≈ [(z_(1−0.05/6) + z_0.80) × σ_d / δ]²

以三比较的 Bonferroni 近似作保守规划，δ 初定 0.03 Brier 改善差。若 σ_d＝0.05，正态近似需要约 30 个独立配置，因此计划 32；若 σ_d＝0.08，则约需 75 个，32 就不足。该数值仅为计划演算，不是实验观测。最终 n、δ 和预算在测试前冻结；不能边看显著性边增加样本。

### 15.3 分层结论，不预设成功

**选择机制得到支持：** Explorer 对三项主基线的改善方向一致，校正后检验支持差异，且估计差达到预先声明的实际意义阈值。若仅胜 Novelty 而不胜 LearningProgress，结论限定为“优于新奇性”，不能声称显式知识缺口超越已有学习进展策略。

**可复用知识得到支持：** M3 中 Explorer 知识相对空知识改善任务表现，并且相对主要探索基线具有一致优势；报告实际效应和区间。主要知识分数改善但任务未改善时，只能说获得了可预测知识，尚未证明任务价值。

**证据组织得到支持：** M2 在相同内容与预算下改善证据／反例检索或修订，并且没有以显著预测退化换取速度。M1 成功不能自动支持这项结构主张。

**机制解释得到支持：** 噪声冗余下降与困难机制覆盖同时改善，才支持 learnability 解释。只有更高总分但没有这些迹象时，可报告性能，不臆断机制。

低功效或宽区间结果标为不确定。只有按预注册等效性设计支持实际差异很小，才能作近似等效结论；不能把 p>0.05 当作“无效果”。

## 16. 信效度、盲审与失败控制

### 16.1 感知与执行的测量可靠性

在 DEV 独立制作不少于 200 段屏幕前后事件，标注目标对应、可见变化、执行可判定性和 UI 图标变化。两名不知道方法标签的编码者独立编码，分歧仲裁；报告类别混淆与一致性，而不是对异质事件直接计算 Cronbach’s α。

建议进入 pilot 的工程门槛：主要事件 macro-F1≥0.90；纯相机运动被误报为对象变化的比例≤0.05；近距离准星／普通 UI 取放验收成功率≥0.90。门槛是本项目建议标准，不是文献结论。若不达标，修正视觉和输入，再冻结所有组的统一版本；不要让某一策略独占修复。

### 16.2 构念与外部效度

通过 same-state selector 诊断检查知识差异是否改变选择；通过规则重排排除简单 MC 记忆；通过 matched executor 排除执行差异；通过新实例测试排除实例背诵；通过空物品栏排除积累物资；通过独立答题会话排除测试回流。

单一模型族的结果只支持该模型与工具约束下的机制。至少用一个不同推理模型在 8 个冻结世界上作方向性复现，放在扩展而非替代主样本；模型版本不同、调用预算不同的结果分开。

### 16.3 常见失败与预定处理

感知合并对象：记录 identity ambiguity，重新观察，不直接写负规律。控制不命中：进入执行诊断，成本仍计入。图检索遗漏反例：记录 truncated 和缺失证据，不能把“没取到”当作“没有”。随机源持续新奇：检查参数不确定性与结果熵是否混用。规律过拟合：用留出实例和条件测试，不能靠增加任意条件消除训练反例。

若所有组几乎全失败，先看通用控制和可解性；若所有组接近满分，说明环境或预算不能区分策略。只能在 DEV/PILOT 调整难度；看到 TEST 后调整必须重新封存新测试集并更新协议版本。

## 18. 资源预算与停止线

320 次 M1，每次最大 24,000 tick，在 20 tick/s 的参考换算下最多约 106.7 小时有效环境运行。M3 的 1,536 个任务每个最多 3 分钟，最多 76.8 小时有效环境运行；两项合计约 183.5 小时，不包含 pilot、重置、评估推理、渲染和硬件等待。它是工作量换算，不是墙钟完成承诺。

M1 最多 61,440 次规划／更新调用（320×96×2）；实际调用依动作长度与其他停止预算而下降。每配置三个快照×48 道预测共 144 道；320 次运行共 46,080 道独立问题，可按相同模型预算批量打包但不得让题目之间写入共享记忆。M2 与 M3 另计。

先在 pilot 记录每轮输入／输出／视觉 token、图像推理耗时、峰值显存、MC 内存、日志增长和查询 p95，再核算：总费用＝各模型输入、输出和图像计费项之和。不要用环境 20 分钟估算 LLM 墙钟时间。

SAM 感知服务使用官方支持的软件环境；具体显存需求依分辨率、并行对象与 checkpoint 而变，本方案不保证某张消费级显卡必定满足。优先短片段／目标式追踪与帧缓存，不让 SAM 对全部历史视频反复推理。[R6]

停止线：版本或泄漏未验收，不跑 pilot；基础控制不可靠，不比较 curiosity；未冻结独立测验，不跑确认性 TEST；预算不足时缩小公开结论范围，而不是只保留最好看的成功轨迹。

## 20. 结论边界与研究标题建议

当 M1、M2、M3 各自提供支持时，可以说：在一个领域先验受限、仅屏幕输入的受控 Minecraft 环境中，知识缺口驱动的实验选择提高了独立知识获取效率，所得经验能够形成有依据的可复用知识；相同经验下的证据组织检验进一步解释了检索与修订收益。

不能仅凭本轮说：智能体完全没有 MC 先验、产生了人的主观好奇、六项原理都已成为定理、发现了最优知识拓扑、掌握了完整 Minecraft，或对所有未来任务更有效。

建议工作标题：**ExplorerLab：通过显式知识缺口与证据记忆实现屏幕具身智能体的主动知识获取**。主贡献应来自“受控比较＋独立知识测量＋迁移与修订证据”，而不是演示长度。
