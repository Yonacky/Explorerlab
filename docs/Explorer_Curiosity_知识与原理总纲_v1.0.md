# Explorer Curiosity：知识与原理总纲

**从主动求知到有证据约束的知识生长**

讨论整理版 v1.0 · 2026-09-27

> 好奇不仅决定下一步做什么，还决定经验怎样成为知识、知识怎样支持尚未验证的推断，以及知识结构怎样产生新的研究问题。

本文整理本轮对话中关于 Curiosity 的六项基本原理、知识与证据的关系、概念树向“有边界的拓扑网络”的演进，以及相应的形式化与实证边界。它是理论与表示层的工作文档，与《Explorer MC Curiosity 实验方案 v1.0》配套，但不重复实验场、样本量和工程配置。

**核心立场**

知识可以增长，也必须能够修订。假说可以明确大胆，确信程度必须与证据相称。抽象结构应产生新的可检验后果；元认知则评估并调节整个认识过程。

**当前状态**

六条主张来自用户；其规范化表述、两项补充约束和数据结构细化来自后续讨论。本文保留这些来源差异，不将设计建议写成已经证明的定理，也不包含真实实验结果。

# 1 研究对象与概念边界

## 1.1 Curiosity 的工作定义

> Explorer 的 Curiosity，是一个受证据与资源约束的知识生长控制过程：它根据可更新的知识状态，提出或发现值得澄清的问题，选择或创造认识情境，并利用所得证据修订信念、形成抽象，继续扩展能够提出和解决的问题。

这一定义综合此前“自主知识获取”“知识边界的主动管理”与“有证据约束的知识生长”三种表述。它讨论功能性机制，不据此主张系统具有人的主观好奇体验。[S1，§1、§29；D1，§1；C2]

## 1.2 Curiosity 不等于整个 Explorer

Curiosity 负责研究什么、怎样研究、何时继续或停止。Explorer 还包含感知、执行、学习、记忆和技能等支持模块。系统表现改善，不能自动归因于好奇选择；一次随机发现也不能单独证明存在知识状态驱动的机制。[D1，§1.2]

同一对象对不同知识状态的智能体可以具有不同研究价值。真正需要检验的是：改变相关证据后，选择是否随之改变，而不只是对象是否更亮、更近或更陌生。[D1，§8.3；C2]

## 1.3 这里所说的“知识”

知识采用工程性的操作定义：关于对象、关系或变化规律的、具有适用条件和证据来源的可检验主张，或相应的概率预测。系统可以保存假说，但不能仅因它被写入记忆就将其标为已经证实的知识。[D1，§2.1；C2]

| 概念 | 在本稿中的含义 | 不能混同为 |
|---|---|---|
| 经验记录 | 实际观察和执行的可追溯记录 | 世界真值或必然正确的解释 |
| 命题 / Claim | 具体的、带条件的主张 | 一段文字本身就是事实 |
| 概念 / Concept | 用于区分类别、属性和关系的结构 | 一个具有统一置信度的词语 |
| 信念 / Belief | 当前对某命题的支持程度与状态 | 新增的一份环境证据 |
| 规律 | 能产生可检验预测的条件性概括 | 无范围限制的绝对结论 |
| 技能 / Skill | 有前置、效果和终止条件的可复用过程 | 被反复执行过的任意动作序列 |

## 1.4 自主性与价值的范围

自主性不等于没有先验。具体问题和实验顺序可由系统生成，但语言模型、感知模型、操作接口与初始模板仍需审计。无任务奖励也不等于无优化目标；第一版不训练 RL 是实现选择，不是好奇的定义。[D1，§1.3]

知识价值与任务价值分开评价。可复验规律未必对某一批任务有用；任务成功也可能来自先验、物品或执行优势。本文不将有限测试中的成功推广为“对任意未来任务都有用”。[D1，§2.5]

# 2 六项基本原理

六条原始表述保留为研究纲领；下述规范化文字来自后续讨论。它们不是六个已证定理，也不要求所有能力都在第一版同时实现。[C1–C2]

## P1 认识增长原理

**原始主张：**“好奇的目的是减少未知，增加知识并发现规律”。

**规范化表述：**好奇以增进对世界的理解为目标，通过澄清未知、修正错误和发现可复用规律，提高解释、预测和进一步研究世界的能力。

必须同时保留两种进展。局部认识进展，是已经提出的问题变得更清楚；知识边界扩展，是发现此前没有表示的变量、关系或问题。前者可能减少局部不确定性，后者却可能增加待回答问题的数量。[C2]

例如，智能体最初只问“对象能否移动”，后来发现效果还依赖接触方式和支撑条件。它获得了知识，同时也发现更多未知。因此，不应以“问题总数下降”“内部熵每次都下降”作为好奇成功的定义。

**对系统的要求：**同时记录已解决问题、被修正的错误，以及新增的可检验问题。认识进步必须由独立预测、复验和迁移来判断，不能靠缩小考虑范围制造“更确定”。

## P2 经验保存与知识化原理

**原始主张：**“好奇需要记住值得记住的东西，并总结成知识”。

**规范化表述：**持续性的好奇需要保存对后续认识有价值的信息，并将具体经验组织为可检验、可修订、可复用的知识。

值得记住的不仅是常见事件和成功轨迹，还包括区分竞争解释的观察、罕见反例、关键失败和适用边界。大量重复成功可以被压缩，但反例和条件不能在摘要中消失。[C2；S1，§15–16]

> 知识化不是“很多经历变成一句总结”，而是“经历形成带条件的主张，并保留来源与未解释部分”。

**对系统的要求：**经验记录、规律候选和抽象结构相互连接；同一记录允许以后重新解释；可压缩重复内容，但要保留其来源、覆盖范围和审计限制。

显式证据图是 Explorer 的设计选择，不是所有好奇系统的逻辑必要条件。其价值需要与等信息、近似等资源的其他组织方式比较。[D1，§9.6；C2]

# 2 六项基本原理（续）

## P3 预测—检验原理

**原始主张：**“好奇需要预测不确定的结果，并进行实验”。

**规范化表述：**好奇应使当前的不同解释产生可区分的预测，并在可行时选择能够区分它们的观察或干预。

一次推动后没有变化，可能意味着对象不响应，也可能意味着动作没有有效接触。重复相同操作未必有价值；能够区分这两个解释的执行核验或条件变化更有认识意义。[C2；D1，§5]

这里保留验证性与探索性两种活动。验证性实验先有问题与竞争解释；探索性活动可能先发生观察、摆弄或组合，随后才形成问题。后一种活动可以提供线索，但不能事后补写成“事前就有完整预测”的实验。[C2]

**对系统的要求：**分别保存计划、事前预测、实际执行、结果记录和后续解释。实验计划不是已执行事件；事件产生了证据，也不自动意味着因果规律成立。

## P4 有依据的外推原理

**原始主张：**“好奇需要能对未知内容给出足够强的信念，因为并不总是能进行实验”。

**讨论中的修订：**保留“能够超越直接经验作出推断”，不保留“无法实验时就应提高确信程度”的解释。

**规范化表述：**当直接实验不可行时，系统应利用已有知识进行有依据的外推，形成可支持决策的暂定信念，同时保留其假设、适用范围与不确定性。

解释能力强，与主观确信度高，是不同性质。明确提出一个可能错误的假说有助于检验；把证据不足的判断赋予高概率，则可能遮蔽真正的未知。[C2]

> 假说可以大胆而明确，确信程度必须与证据相称。

**对系统的要求：**区分已观察、由已有规律推导、类比预测和内部模拟。对于新对象的外推，应说明源于哪些经验，哪些条件没有验证。可以保留判断，或在多个解释下选择较稳妥的行动，不必为了行动而制造确定性。

暂时不能实验的问题应保留重新打开条件。当新的对象、工具、技能或情境出现后，未验证预测可以回到真实实验队列。[C3]

# 2 六项基本原理（续）

## P5 结构改进原理

**原始主张：**“好奇需要主动拓宽知识的边界，总是主动寻找更高效的结构”。

**规范化表述：**好奇不仅更新既有结构中的答案，也主动寻找更有效地组织经验、生成预测和支持迁移的表示结构。

拓宽认识范围与改进内部结构相互配合，但不完全相同。结构变化可能是实例归类、类别拆分、增加条件变量、改写关系或组合技能；未必总是建立一个更大的父节点。[C2–C3]

“更高效”不能只按节点更少、描述更短或连接更多判断。讨论中保留的标准是：在维持预测与迁移表现时降低存储、检索和推理成本，或者在适当增加复杂度后取得可独立验证的预测改善。

**对系统的要求：**概念与结构修改作为可审计提案处理；检验新结构能否解释原有证据并预测新经验；允许撤回、拆分和回退。聚类与摘要可以生成候选概念，但不能直接成为概念有效性的证据。

“知识应该组织为树”本身也不是不可修订的先验。后续讨论已将整体组织改为有类型、有边界的网络，树仅保留为某些层级关系的视图。[C1–C3]

## P6 情境生成原理

**原始主张：**“好奇不满足于现状，总是主动去制造新的情况”。

**规范化表述：**当现有情境不足以产生新的认识时，系统应能够主动构造新的对象关系、操作组合或环境条件，创造学习机会。

P3 关注怎样检验当前解释；P6 进一步关注如何使原本不存在或不可执行的实验成为可能。准备动作可能几乎没有即时信息收益，却能打开后续研究范围。[C2]

**对系统的要求：**把前置条件、技能依赖和新情境构造纳入实验计划；记录为何需要先准备，再观察。已经学会的动作和规律，应能参与生成更高级的问题与实验。

“不满足现状”被保留为持续寻找新认识机会的倾向，而不是每一时刻都必须改变世界。等待、复验、整理证据、暂缓和停止无效实验，同样可能是合理的认识活动。

六条原理共同形成：**经验保存 → 有条件知识 → 预测与实验 → 有依据的外推 → 结构改进 → 新情境与新问题。** 这是功能关系，不是固定执行顺序。

# 3 两项贯穿性约束

这两项是后续讨论提出的补充，不改写为用户原始六条中的内容。它们约束所有求知活动，避免系统只会积累解释而不会控制错误。[C2]

## 约束 A：反证与修订

系统不仅要增加主张，还要能够降低确信、撤回判断、缩小范围和拆分概念。反例不是必须立即删除旧规律的命令，也不是可以忽略的噪声；它触发对执行、观测、条件和解释的诊断。

不同修订应有不同语义：对象位置改变，是状态更新；原位置记录错误，是信念纠错；规则只在部分条件成立，是范围修订；多个实例原本不应归为同类，是结构修订。

一份依据失效时，只重评受影响的支持关系。若结论还拥有其他独立依据，不能沿图机械地撤回全部后代；同样，也不能让失效支持继续通过高层摘要存在。[C3]

**研究上的约束：**每条被标为已有经验支持的主张，应能追溯到真实记录或明确的推导谱系；来源可追溯仍不等于归纳正确，后续独立验证不能省略。

## 约束 B：元认知与资源调节

系统需要判断当前缺少的是观测、规律、执行能力，还是合适的表示，再决定继续实验、换一种实验、进行推理、暂缓或停止。

资源包括时间、环境交互、计算、上下文和原始证据存储。实验还受到可执行性、允许动作与风险边界约束；收益分数高，不能代替执行许可和停止条件。[S1，§17；D1，§3、§11]

低学习进展应区分原因。可能已经掌握随机分布，也可能缺前置技能、实验失败或模型漏掉条件。问题暂缓时记录阻碍；新条件出现后再打开，而不是永久标记为“无聊”或“不可学习”。

## 六项原理与两项约束的关系

六项原理规定需要发展哪些求知能力；反证约束规定如何避免错误累积；元认知与资源约束规定如何调节这一过程。它们共同构成研究纲领，而不是要求以一个总分替代全部能力。

一个有效系统应同时表现为：能学会，也能承认未学会；能复用，也能识别越界；能创造情境，也能停止无增量重复。是否实现这些行为，必须通过独立记录与对照判断，不能从自述中直接认定。

# 4 未知、可学习性与元认知

## 4.1 已表达的未知与尚未表达的未知

已表达的未知，是系统已经能提出问题，但答案尚不清楚。尚未表达的未知，是当前模型缺少相关类别、条件变量或解释方式。前者可以进入问题队列；后者只能通过异常、预测失败和概念冲突逐步转化为新问题，不能预先完整列成图的“外圈”。[D1，§2.2；C3]

因此，“知道自己不知道什么”是有范围、可犯错的能力。只发现预定义槽位的空缺，不能直接称为开放式未知发现。

## 4.2 不确定性采用属性与来源两个维度

属性维度回答哪里不知道：身份、位置、几何、语义、affordance、动力学或因果条件。来源维度回答为什么不知道。[S1，§4–5；D1，§2.3]

| 未知来源 | 典型解释 | 优先检查的方向 |
|---|---|---|
| 规律知识不足 | 没有尝试相关条件或动作 | 有区分力的观察、干预与复验 |
| 当前观测不足 | 遮挡、出视野、对应不明 | 重观察、视角与身份核验 |
| 结果具有随机性 | 同条件下允许多种结果 | 学习分布和条件依赖 |
| 表征或模型不足 | 分割错误、遗漏变量 | 检查感知与表示结构 |
| 世界发生变化 | 位置、环境条件或规则改变 | 时效性维护与重新学习 |

这是诊断框架，不假设系统已能准确分解全部来源。单个预测误差不能直接指出是哪种原因。

## 4.3 Learnability 与 learning progress

Learnability 是对未来有限预算内能否改善认识的判断；learning progress 是已经观测到的改进。后者可用于估计前者，但不能与前者等同。新问题还没有学习进展，不等于没有学习价值。[D1，§2.4]

随机性不等于无知识可学。单次随机结果可以仍然不可预测，但概率分布可能已被掌握。目标是减少对已掌握随机机制的无增量重复，同时保留对困难但可学习问题的研究。[D1，§9.4]

## 4.4 元认知不是概念网络的最高类别

世界知识回答“世界怎样变化”；元认知回答“我的哪些判断可靠、根据是什么、哪些推断或观测方式容易失效，以及怎样研究更有效”。抽象层级、证据充分程度和元认知不是同一条高低轴。[C2]

“动作效果依赖接触条件”是世界知识；“仅凭外观外推时，我在某些情境中容易过度自信”是元认知判断。后者也要依赖跨事件的预测—结果记录，不能由一次失败或一段自述确立。统一根节点可以是软件入口，但其位置本身不构成元认知能力。

# 5 经验如何成为证据

## 5.1 事件、实验计划和解释分别保存

经验事件包含主动观察、主动干预和被动遭遇。三者均可能产生知识线索；只有在确实存在事前计划时，才记录相应预测与实验设计。内部模拟、类比和思想实验另记为推演，不与真实环境事件混算。[C2–C3]

| 事件记录的内容 | 需要保留的区别 |
|---|---|
| 情境与目标 | 对象对应、可见条件、时间及世界版本 |
| 观测来源 | 截图、片段、动作日志及其稳定引用 |
| 计划与预测 | 没有事前计划或预测时明确记为空 |
| 实际执行 | 发出动作不等于动作成功作用于目标 |
| 结果与观察窗 | 何时观察、看到了什么、可检测程度 |
| 质量与局限 | 遮挡、匹配疑点、执行失败和遗漏条件 |
| 解释与关联 | 哪些命题受支持、受挑战或仍不可区分 |

在 screen-only 设置中，保存的是屏幕记录和状态估计，不是智能体不能访问的真实坐标或世界状态。研究者的评分真值需要与执行通道隔离。[D1，§7.4；E1，§4]

## 5.2 世界变化与表征变化分开

“对象不见了”首先意味着不再被当前观察到，不能直接推出对象消失。此前的 Transport Before Dynamics 原则要求先检查观察者运动、参考系变化和表征误差。[S1，§12；D1，§4.3]

$$
 r=z_{t+1}-T(z_t;\Delta p)
$$

这里的位姿变化必须由允许的视觉与动作历史估计。残差显著仅触发进一步诊断，不能单独证明真实变化，更不能证明该变化由刚才的动作造成。

## 5.3 没有变化也可以是证据，但必须可解释

负结果的意义依赖动作是否成功执行、观察窗口是否充分、变化是否可检测。没有执行核验，就无法区分“对象没有响应”与“动作未作用到对象”。记录不能只保留显著变化，否则会丢失必要的否定信息。[C2；D1，§5]

## 5.4 记录保留，解释可修订

某次事件起初可能被解释为对象固定，后来才发现接触失败。正确更新是建立新的解释与信念版本，不改写当时发生的记录。类似地，动作后的变化先作为转移预测或因果候选；需要匹配条件、替代解释、对照与重复证据，才能讨论一定范围内的干预支持。[C2–C3；E1，§11]

# 5 证据支持与知识状态（续）

## 5.5 每条知识有证据责任，但不要求一条知识独占一次实验

一次经验可以支持多条命题；一条命题通常也需要多次经验。抽象概念可以通过下层主张间接连接观察，不要求每个概念拥有一项独占实验。但间接连接需要能够审计，并产生可独立检验的后果。[C2]

> 被标为“已有经验支持”的世界知识，必须能够沿证据或推导关系回到真实记录；没有直接实验依据的节点可以存在，但应明确其身份。

没有实验节点直接指向，不能推出“它一定是抽象规律”。它也可能是先验、未验证预测、类比推断或暂时无依据的假说。位置更高也不代表更可靠。[C2]

## 5.6 命题内容、支持程度与适用范围分开

“某类对象在条件 c 下发生结果 y”是命题内容；当前支持程度是信念状态；哪些情境被实际测试，是证据范围。改变其中一项，不应无痕改写其余部分。[C3]

| 记录维度 | 示例状态 | 作用 |
|---|---|---|
| 来源身份 | 观察、归纳、推导、类比、先验 | 说明判断来自哪里 |
| 认识状态 | 候选、初步支持、复验、受挑战、失效 | 说明当前应如何使用 |
| 范围 | 已测试范围、拟推广范围 | 防止经验外推冒充已验证 |
| 修订历史 | 旧版本、新版本、替换或限定原因 | 支持回溯与纠错 |
| 验证记录 | 独立预测、复验、反例、校准 | 检验质量而非只读置信分数 |

这些维度不能压成一个通用 confidence。命题可以范围很窄却证据充分，也可以高度概括但尚未验证。内容实质改变时建立新版本；仅支持程度变化时记录新的信念修订。

## 5.7 不重复计算同一份实证支持

E1 被用于形成 P1，P1 再参与 P2 和 P3，不等于 P3 获得三份独立环境证据。同一段录像被多个模型解释、被多个摘要引用，也不产生新的独立观察。[C2–C3]

系统需要保存证据谱系与原始来源 ID。不同 ID 也不自动意味着统计独立；采集批次和共享条件仍可能造成依赖。来源可追溯是审计条件，不是主张成立的充分条件。

## 5.8 证据与摘要的不同责任

摘要、推理与抽象可以显化已有经验中的结构，使其更易检索和使用；它们有认识价值，但不能伪装成额外实验。删除原始记录时，应明确剩余审计能力，不能仍声称能够完整复现。[C2–C3]

# 6 有边界的拓扑网络

## 6.1 从树到网络：保留层级，不强迫单父结构

最初的树形设想强调“概念有层级、知识有证据”。后续修订保留了这两个目标，但不再要求每个节点只有一个父节点，也不把最高抽象归结为元认知。[C1–C3]

同一对象可以同时参与多个类别与规律；同一实验可以支持多个主张；抽象、证据、因果候选、时间与技能依赖具有不同关系类型。因此，树适合作为某种层级视图，不适合作为整个知识系统唯一的结构。

此前提出的组织方式是：**证据驱动、带类型、带情境与时间的动态超关系图；每轮认识活动只激活一个有预算的局部工作子图。** 这是 Explorer 的架构建议，尚不是已经验证最优的表示。[C3]

## 6.2 四种边界

| 边界 | 回答的问题 | 在系统中的表达 |
|---|---|---|
| 认识边界 | 当前已提出但尚未澄清什么？ | Question、竞争解释、状态与阻碍 |
| 适用边界 | 某条知识在哪些条件下可使用？ | 已测试范围与拟推广范围 |
| 计算边界 | 本轮允许读多少、算多少？ | 工作子图、读取预算与截断标记 |
| 模块边界 | 哪些知识适合一起处理？ | 可重叠模块、共享 ID 与跨模块连接 |

缺失关系不等于关系为假；没有加载不等于不知道；不知道也不等于不存在。上述三种情况必须在查询接口与结果中分开。[C3]

认识前沿只包括当前可表达的问题：

$$
F_t=\{q\in Q_t:q\text{ 已提出且尚未充分澄清}\}.
$$

不能把所有可能的未知预先编码在网络外围。模型之外的未知，需要通过异常和结构冲突进入问题空间。

## 6.3 模块、概念和拓扑不是同一件事

模块用于计算和检索组织；概念用于描述世界差异。节点经常共现、聚在同一社区，不直接证明它们形成了有效概念。模块允许重叠，但底层实体不应因此被复制成多个身份。

“拓扑”在本讨论中指连通与关系结构，不额外承诺流形或其他严格几何性质。整个图可以有环；需要约束的是特定关系。例如具体版本的推导谱系应防止结论绕一圈再次充当自己的证据，而不是把全部知识统一强制为 DAG。[C3]

# 6 六类节点与带角色连接（续）

## 6.4 最小元结构

固定的是认识活动的组织方式，而不是 Minecraft 的对象类别或领域规则。上下文、模型参数等可先作为记录；需要独立引用时再提升为节点。[C3；E1，§6.3]

| 类型 | 主要内容 | 核心责任 |
|---|---|---|
| Anchor | 对象实例、原型、概念、区域及其稳定 ID | 明确知识在谈论什么 |
| Claim | 观察判断、状态判断、条件规律、预测和元认知判断 | 明确系统具体主张什么 |
| Episode | 实际观察、执行、时间与原始数据引用 | 明确记录到了什么 |
| Procedure | 动作模板、实验计划、技能与组合过程 | 明确怎样观察、干预或准备 |
| Question | 未知维度、竞争解释、候选实验、阻碍与状态 | 明确认识前沿 |
| Justification | 证据、前提、假设、方法和修订关系 | 明确为何得到或改变判断 |

## 6.5 关系必须有类型，也必须保留参数角色

“属于”“支持”“反对”“由此推导”“需要此前置条件”和“在某时间有效”不是同一类边。将它们都写成“相关”，会丢失推理与证据责任。[C3]

有条件规律同时涉及对象、动作、情境和结果：

$$
R_{12}:(O\in C_4,A=A_7,c=C_9)\mapsto P(\Delta O,\Delta UI).
$$

把它拆成“C4 与 A7 有关”“A7 与某结果有关”会丢失条件同时成立的含义。此前建议让规律本身成为节点，以 target、action、context、outcome 等角色边连接参与项；逻辑上是超关系，物理上可用普通属性图编码。[C3]

## 6.6 一个关系结构示例

以下仅是模式示例，不是实际实验记录：

```text
Episode E31、E45 ──输入──> Justification J8
Justification J8 ──形成信念修订──> Claim R12
Claim R12 ──对象类别 / 动作 / 条件──> C4 / A7 / C9
Question Q5 ──询问适用范围──> Claim R12
Question Q5 ──候选实验──> Procedure P6
```

R12 的主张内容、信念参数和已测试范围分别保存。J8 记录使用的证据与假设；Q5 不等于知识缺失的任意空边；P6 也不等于已经发生的 Episode。原始经验被多次使用时共享来源，不复制成额外独立证据。

# 6 多视图、时间与计算组织（续）

## 6.7 一套记录，多个读取视图

| 视图 | 读取重点 |
|---|---|
| 世界视图 | 对象、位置、关系和当前可用规律 |
| 证据视图 | 事件、命题、反例、来源与推导链 |
| 研究视图 | 未解决问题、竞争解释、实验与前置条件 |
| 元认知视图 | 校准、执行可靠性、学习进展和推断失效条件 |

各视图共享稳定 ID，不是四套重复知识。高频查询可以使用简化投影边，但必须保留对应命题、情境与版本引用。投影是缓存，不是新增事实来源。[C3]

## 6.8 时间和版本分开

有效时间表示主张描述世界的哪个时段；记录或修订时间表示系统何时取得或修改这一认识。对象状态真的变了，与系统后来发现旧判断错了，必须能被区分。

新观察也不能自动覆盖旧观察。冲突可能来自世界变化、身份匹配、不同情境、执行失败、模型遗漏条件或新观测错误，需要诊断后修订。[C3]

## 6.9 局部工作子图与分级保存

$$
W_t=\operatorname{Retrieve}(G_t,q_t,c_t,B_t).
$$

长期图为 G，当前问题为 q，情境为 c，读取与计算预算为 B。工作层保留当前问题、局部状态与必要依据；知识层保存长期主张、技能和索引；档案层保存原始影像、详细轨迹与旧版本，按需取回。[C3]

检索先以身份和条件定位，再以相似度召回候选，然后沿允许关系扩展，并补齐关键依据、反例和跨模块前置条件。相似不等于同一，关联强不等于证据强。

限制跳数不足以限制高连接度节点的扩张，还需限制节点、边、证据展开数与 token 或字节总量。查询结果应报告是否被预算截断，防止模型把未取回当成不存在。

## 6.10 工程建议的身份

此前提出以属性多重图编码、关系型持久化、双向邻接索引和外部原始数据存储实现单机原型。该建议不等于某种数据库在所有规模下最优，也不把图结构当作自动的概率推理器。[C3]

逻辑结构、存储后端、局部推理模型和 Curiosity 选择器是四项不同设计。理论文档保留其职责边界；具体容量、预算与冻结参数以实验协议为准，不在本稿另设数值。

# 7 Curiosity 如何驱动知识网络生长

## 7.1 从知识状态到下一轮认识活动

此前讨论的闭环可以按责任整理为以下过程，不将它规定为只能按单一固定顺序执行的流水线。[S1，§22；D1，§4；C3]

| 环节 | 核心问题 | 应留下的记录 |
|---|---|---|
| 感知与维护 | 当前对象、状态与旧知识是否对应？ | 来源、身份、时效与疑点 |
| 问题生成 | 哪项未知或冲突值得进一步澄清？ | 问题、触发原因、未知维度 |
| 候选实验 | 怎样使不同解释产生不同证据？ | 计划、预测、观察窗、前置条件 |
| 选择与执行 | 当前预算下先做什么，实际做到了什么？ | 候选评分、选择、执行核验 |
| 证据更新 | 结果支持或削弱了哪些主张？ | Episode、Justification、信念版本 |
| 复验与抽象 | 哪些经验可推广，哪里需要改结构？ | 复验、反例、范围与结构提案 |
| 重新分配 | 继续、暂缓、重开还是研究新问题？ | 状态变化与下一步依据 |

记录“为何选择”应保留可检查的输入、候选与评分，不把事后生成的解释文字当作选择机制的证据。[D1，§4.1]

## 7.2 问题节点不是所有缺失关系的枚举

此前提出的主要触发包括：无法解释的观察、相互冲突的命题、准备外推到未测试条件、重要状态信息过时，以及新技能或物品使旧问题变得可研究。[C3]

Question 至少应指出目标、未知维度、竞争解释、候选过程、阻碍与状态。问题可以暂缓，但保留重开条件。若对所有对象×动作×条件枚举未知，图可能增长很快，却未必增加有价值的研究机会。

## 7.3 观察、干预与情境准备

能够通过重观察解决的问题，不应无必要地干预。该原则按证据需求区分活动，不按智能体是否移动区分；移动相机仍可属于主动观察。观察也可能提供动作效果线索，交互也可能帮助核验身份。[D1，§4.2]

当当前条件不足时，Procedure 可以先准备物品、调整关系或执行前置过程，再取得证据。短期信息收益低的准备，不应自动被长期价值判断排除。[C2]

## 7.4 生成质量与选择质量分别研究

共享候选生成器可以用于比较选择策略，但不能证明开放式问题生成。在线历史不同，候选内容也会不同；“使用同一生成器”不等于“每一轮得到完全相同候选”。固定候选回放与闭环探索回答不同问题。[D1，§7.2；E1，§7.1]

# 7 增量修订、抽象与技能（续）

## 7.5 更新是增加记录并修订支持关系

此前建议的更新顺序为：追加 Episode；提出或修订 Claim；写入 Justification；沿反向依赖定位受影响结论；重评支持状态；更新问题与当前视图。[C3]

“受影响”不等于“必然为假”。一个结论可能有多条依据；撤掉其中一条后，应重评而非全链删除。反之，旧结论的摘要或投影，也不能在源依据失效后无痕继续生效。

若主张内容改变，应保留新旧版本及原因。若只是世界状态改变，应保留有效时间差异；若发现旧记录误解，应保留纠错与解释版本。增量维护的价值仍需按实际更新成本和遗漏率检验，不能预设它总比重算更快。

## 7.6 结构改进的五类操作

增加条件，说明规律并非无条件成立；拆分类别，解释成员之间可复现的差异；合并类别，消除对相关预测没有必要的区分；形成规律或技能，复用跨实例或跨轨迹结构；撤回或替换关系，纠正错误分类与依赖。[C3]

这些操作是结构提案，不是自我验证。先检查类型、来源、版本与依赖是否一致，再用新经验评价预测和迁移。图结构合法，只说明数据符合约束，不说明世界主张正确。

## 7.7 技能是知识生长的产物，也扩展实验能力

经验可按 trace → pattern → skill 组织；技能可成为组合技能的节点。实例也可形成原型、类别和更高阶关系。但反复出现不自动意味着可靠抽象，仍需前置条件、预期效果、终止条件、失败模式与复验证据。[S1，§16；D1，§4.5]

技能既可以是被研究的知识，也可以是后续实验的执行能力。比较系统时要控制是否允许宏技能，否则更好的任务表现可能来自执行接口变化，而非知识获取或选择策略。

## 7.8 一个贯穿示例：反例怎样改变结构

以下沿用讨论中的假想情境，不是运行结果。O17、O18 在操作后出现位移，系统形成关于某外观类别的候选规律；外观相近的 O19 没有位移。此时可能是执行失败、外观并非相关特征、支撑条件不同，或存在遗漏变量。[C2]

系统据此提出区分性实验，核验执行并比较条件。结果可能使类别拆分、给规律增加条件，或降低仅凭外观外推的权重；未必需要增加更高层父节点。若多个案例都显示同类外推失误，才有依据形成关于该推断方式的元认知判断。

这一例子连接六项原理：保存反例、提出解释、预测并检验、保留暂定信念、改进结构、主动构造新条件。

# 8 形式化：目标、估计与结果分开

本节归档此前讨论中的数学表达，不新增算法承诺。规范性目标说明希望优化什么；内部估计服务选择；独立评价决定是否真正取得知识。[D1，§3、§9]

## 8.1 规范性研究目标

$$
\pi_C^*=\arg\max_{\pi_C}\mathbb{E}[V_{\mathcal Q}(K_T)-V_{\mathcal Q}(K_0)]
$$

$$
\sum_{t<T}\operatorname{Cost}(e_t)\le B,\qquad e_t\in\mathcal E_t^{\mathrm{admissible}}.
$$

K 是知识状态，Q 是声明的评价问题范围，V 是该范围内的知识质量，B 是预算。可接受实验集合体现许可、可执行性和停止条件。智能体不能读取隐藏评分答案来估计真实收益。[D1，§3.1]

## 8.2 局部预期信息增益

$$
\operatorname{EIG}_t(e,q)=\mathbb E_{Y_e}\!\left[D_{\mathrm{KL}}\!\left(b_t(\Theta_q\mid Y_e,e)\Vert b_t(\Theta_q)\right)\right].
$$

该表达依赖明确的问题参数、结果空间、似然和 belief。图负责组织与检索，不自动提供这些概率模型。局部模型错了，内部 EIG 也可能误导选择；高 EIG 不能独自证明学习正确。[D1，§3.3；C3]

## 8.3 信念变化不是知识真值

原稿曾将实验前后 JS divergence 称为 IG；后续明确改为 belief shift。为避免与 MC 协议中的 Brier score 缩写混淆，本稿写全称而不复用 BS。[S1，§7；D1，§9.1；E1，§10.3]

$$
\operatorname{BeliefShift}(e)=D_{\mathrm{JS}}(P_{\mathrm{before}}\Vert P_{\mathrm{after}}).
$$

它衡量变化幅度，不保证改变得更正确。前后分布还必须具有可比较的变量与支持集。表示空间改变后，不能直接将任意分布差异解释成信息增长。

## 8.4 学习进展与启发式的边界

在线 learning progress 应比较历史与当前模型在同一组已获得探针上的损失，而不是使用未来窗口。探针不应回流隐藏测试答案；样本覆盖与反复使用仍可能影响估计。[D1，§9.3]

原稿的加权 score 与“未知×可学习×信息收益”属于不同候选启发式，不是同一个定理。权重、量纲、重复计分和新问题的初始尝试必须明确；不能用尚未观测到的 LP＝0 永久拒绝新实验。具体实现参数以 MC 协议为准。[D1，§3.4；E1，§7]

# 8 两个有条件的数学命题（续）

以下是前次讨论中用于约束系统的标准概率关系，不是声称提出了新的数学定理。它们不等于对六项原理或完整 Explorer 的经验性证明。[C2]

## 命题 A：固定问题空间内，预期熵下降非负

**条件。** Θ 是有限假设变量；D 是已获得数据；实验 e 在给定 D 后被确定或按不引入额外真值信息的策略选择；先验、似然和更新属于同一个相容概率模型。

$$
H(\Theta\mid D,e)-\mathbb E_{Y\mid D,e}[H(\Theta\mid D,Y,e)]
=I(\Theta;Y\mid D,e)\ge0.
$$

**推导摘要。** 条件互信息是条件先验熵与期望条件后验熵之差；也等于 posterior-to-prior KL 的期望。KL 非负，因此上述期望不为负。若 e 在 D 下固定，可相应省略不提供额外信息的条件 e。

**解释范围。** 这是同一模型、同一假设空间中的平均关系，不要求每一次实际后验的熵都下降。单次反例可能揭示过度自信，使分布更分散。若系统新增变量、改变概念或扩展假设空间，不能直接用该式比较不同空间的“总未知”。

因此，P1 与 P5 并不冲突：旧问题可以更清楚，同时新问题可以更多。

## 命题 B：已有证据的确定性重述不增加独立观测

**条件。** D 是已经保留的完整数据；R＝f(D) 是在固定表示与规则下的确定性摘要或重述；没有通过 R 引入新的外部观察或额外信息。

$$
P(\Theta\mid D,R)=P(\Theta\mid D).
$$

**推导摘要。** 给定 D 后，R 已经确定，因此再次条件化在 R 上不会增加约束或改变该模型的条件分布。

**解释范围。** 这不否定摘要、计算和抽象的价值。计算受限的系统可以通过重组数据，得到此前未算出或无法有效检索的结论；但不能把这种改善计为新增的一次环境实验。若摘要同时利用了额外先验或其他资料，必须把这些输入明确列入来源，而不再称为“仅由 D 得到”。

该命题约束证据计数：同一记录经过多层摘要和推导，仍不能累积成多份独立实证支持。

## 原理、定理与研究假设的分工

六项原理规定研究目标与能力；上述命题规定形式化条件下的关系；H1–H3 检验具体机制能否产生预期效果。三者可以相互支撑，但不能彼此替代。

# 9 信效度与有效性如何研究

## 9.1 智能体的知识，与研究者的理论分开

智能体维护关于世界的命题与证据；研究者维护关于 Curiosity 机制的假设与实验。一次交互可以支持某对象的动作效果，却不能单独证明整个系统更好奇或更有效。[C2]

同样，定义里写了知识增长，不表示系统已经增长了知识；模型自述“我正在研究未知”，也不构成选择机制的独立证据。

## 9.2 对知识节点的检验

| 评价对象 | 研究问题 | 此前讨论的检验方式 |
|---|---|---|
| 观察与编码 | 记录是否可重复、是否受编码方式影响？ | 固定材料的独立编码、观测扰动、执行核验 |
| 条件规律 | 匹配条件下是否可复现？ | 独立重复、跨时间与跨实例复验 |
| 概念结构 | 区分的是相关因素还是无关外观？ | 条件与干扰因素交叉变化、独立预测 |
| 外推 | 未参与归纳的情境是否仍适用？ | 留出实例、条件组合与新环境 |
| 元认知 | 自认为可靠的判断是否真的更可靠？ | 事前置信与实际表现、预计收益与结果 |

随机规律的复现关注结果分布，不要求每次结果相同。重测还需记录模型与世界版本，避免把已经发生的学习或环境变化误判为测量不可靠。[C2]

信效度不宜压成一个节点总分；也不能把每次实验当成量表题项，直接计算 Cronbach’s α 就宣称构念成立。此前讨论强调的是测量对象、模型前提和独立证据的匹配，而不只是增加一个统计系数。[C2]

## 9.3 对 Curiosity 机制的三项核心假设

H1：知识缺口驱动在相同基础设施与预算下，提高独立知识质量或单位交互效率。只增加内部 score、节点数量或访问范围，不足以支持该假设。[D1，§6]

H2：learnability-aware 分配减少无增量的噪声重复，同时不放弃可学习的困难问题。只远离噪声但回避全部难题，不算实现该机制。[D1，§6]

H3：积累的知识有助于保持与复用；结构化组织在等内容条件下改善追溯、修订或检索。这两个分命题需要分别检验，不能把迁移成功直接归因于图结构。[E1，§2.3、§12–13]

## 9.4 独立验证与归因边界

发现数据与验证数据分开；隐藏答案不回流；控制感知、执行、候选生成、记忆内容和资源差异。固定经验流评价组织方式，闭环交互评价探索后果，二者不能替代。结果应报告效果与不确定性，不把单次成功或不显著自动解释为整体证明或反驳。[D1，§7–8；C3]

# 9 与 MC 实验方案的接口（续）

本节只概括已交付协议的理论映射，不修改其参数或重复工程规格。以下都是设计与预期检验对象，尚无 Minecraft 运行结果。[E1]

## 9.5 M1、M2、M3 分别承担什么证据责任

| 实验 | 协议中的关键控制 | 可检验的命题 |
|---|---|---|
| M1：实验选择 | 五臂共享感知、执行、记忆、候选生成方法和预算，替换选择策略 | 是否更有效取得独立可测知识 |
| M2：知识组织 | 同一经验流、命题、证据字段与读取预算；比较 Graph 与 FlatEvidence | 组织方式是否改善反例检索、修订与效率 |
| M3：知识迁移 | 新实例、新布局、空物品栏；保留规则与知识；每任务独立重置 | 知识是否提高新目标表现 |

M1 的主对照为 Random-C、Novelty、LearningProgress、LLM-Choice、Explorer。各组共享生成器，但由于历史不同，在线候选可以不同。主要终点是隐藏预测测验上的 Brier 损失改善，不是 belief shift。[E1，§7–10]

M2 的平面对照保留相同内容和证据字段，不是故意删掉证据的摘要。图的额外存储与维护成本需要报告。M3 排除既得物品和位置优势，主测试还不允许调用新学技能宏，避免混入执行能力差异。[E1，§12–13]

## 9.6 六项原理在当前协议中的覆盖

| 原理 | 当前协议可观察的证据 | 仍不能据此声称 |
|---|---|---|
| P1 认识增长 | 独立预测改善、跨实例复验 | 全领域知识增长或未知总量下降 |
| P2 经验知识化 | 证据追溯、同流组织对照、迁移 | 显式图是知识的普遍必要条件 |
| P3 预测检验 | 事前预测、执行核验与有限对照 | 每段解释都是因果发现 |
| P4 有依据外推 | 禁止追加交互的隐藏预测 | 高自报置信就等于可靠判断 |
| P5 结构改进 | 条件拆分、类别复用与预算内检索 | 自动发现最优本体或无限概念 |
| P6 情境生成 | 前置物品、可见条件变化、组合操作 | 无界开放式环境创造 |

当前图存储与局部读取预算是协议配置，不是原理常数。技能开启、selector×memory 在线交叉对照以及更开放的问题生成，属于分开的扩展，不写成已完成证据。[E1，§2.4、§12–14]

## 9.7 从有限结果到有限结论

只优于 Novelty，不能宣称优于 LearningProgress；预测改善但迁移未改善，只支持预测性知识增长；M1 成功不能替代 M2；受控实验场成功也不等于掌握开放世界或全部元认知能力。[E1，§15、§20]

# 10 讨论修订台账与开放问题

## 10.1 关键修订记录

下表保留早期说法及其后续处理，不将修订后的措辞追认为原始主张。[C1–C3；D1，§9]

| 早期表述 | 后续保留的方向或限制 |
|---|---|
| 好奇减少未知 | 局部未知可减少，同时问题空间可扩大 |
| 对未知给出足够强信念 | 推断要有力量，确信度仍服从证据 |
| 总是制造新情况 | 持续寻找认识机会，不强制不停干预 |
| 概念组织成一棵树 | 网络为整体，树仅作部分层级视图 |
| 每个节点有独占实验支持 | 允许多对多和间接支持，要求可追溯 |
| 无实验指向就一定是抽象 | 也可能是先验、预测或未验证假说 |
| 最抽象根节点就是元认知 | 元认知的对象是认识过程，不由位置决定 |
| JS divergence 是知识增益 | 仅记信念变化；知识质量独立评价 |
| 随机结果或低进展就不值得研究 | 分布可学；需区分难题、缺技能与无增量 |
| 显式 Memory 是知识的必要条件 | 它是 Explorer 的待验证架构选择 |
| 动作后变化就是因果规律 | 核验执行、条件、替代解释和干预支持 |
| 图连接或摘要更丰富就是更好 | 同时检验预测、迁移与资源成本 |

## 10.2 当前仍未定案的研究问题

**开放性。** 第一版能新增哪些变量、概念和问题类型？固定槽位、可变模板与真正开放式发现需分级报告，不能混在同一能力名称下。[D1，§12]

**支持与停止标准。** 不同规律需要怎样的复验、校准和反例处理，何时暂缓或重新打开？当前讨论给出方向，没有统一的普遍阈值。[C2–C3]

**边界与遗忘。** 怎样在存储成本、代表性样本、反例保留与未来重新解释之间取舍？局部检索如何控制跨模块反例的漏检？这些仍要测质量—资源权衡。[C3]

**结构与元认知。** 哪些条件拆分或技能组合真正扩展了实验空间？系统对自身推理方式的判断是否校准？不能用节点增加或自然语言自述代替验证。[C2–C3]

**长期价值。** 有限任务上的效用、长期知识价值和探索成本如何权衡？本稿不预设一个能统一解决这些问题的总分。[D1，§2.5、§3]
