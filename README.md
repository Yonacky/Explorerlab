# ExplorerLab environment

The experimental platform is pinned in `config/platform.example.json`: Minecraft Java 1.20.1, Fabric Loader 0.19.5, Fabric API 0.92.12+1.20.1, and JDK 17. Copy it to `config/platform.json` and set the local JDK and HMCL paths. The machine-specific file is ignored by Git. The local validation uses an offline account. This replaces the 1.21.1 platform assumption in the v1.0 experimental proposal; the protocol must be amended and frozen before pilot or TEST runs.

On this Windows host, `scripts/enter-dev.ps1` sets `JAVA_HOME` and `PATH` for the current PowerShell process. `scripts/preflight.ps1` checks the HMCL instance and reports missing runtime evidence. The installed JDK is valid, but the machine-wide `PATH` does not expose it; the project script supplies the correct JDK without changing other applications. No game credentials or researcher truth are stored in this repository.

The isolated HMCL instance has launched successfully with Fabric API. The first G0 mod is compiled with `python scripts/build-local-mod.py` using the already installed HMCL jars and is installed in that instance. It observes server ticks; it does not pause the world or expose hidden state. The Gradle/Loom project files are present but have not been built because this terminal cannot reach the dependency repositories. The local builder verifies installed JAR hashes before compiling.

The ExplorerLab entrypoint passed a local launch check on 2026-09-27: the log recorded its startup and 625 server ticks before normal shutdown. `scripts/capture-game.py` is a diagnostic screenshot bridge that captures the foreground Minecraft client area as a PNG while returning only image metadata. It still needs a live-window check. The remaining G0 gates are a low-level keyboard/mouse bridge, a controlled effective-tick clock, and a private researcher log separated from agent-visible input. The custom mod must pass those gates before any pilot data are treated as experimental results.
